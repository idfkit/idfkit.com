The idfkit identity

One mark, one accent, one pair of typefaces, on every idfkit host and repository. This page describes the standard at identity-2026.2, the version the site you are reading renders; every file here is generated from that tag and can be downloaded from its release.

The mark

A block with one piece lifted out of its slot: a kit of parts that fit together, as an EnergyPlus model is objects assembled into a building. It is drawn on a 48-unit grid in one colour and is never drawn in two colours, never outlined, never rotated, and never given a gradient. Inline, it takes the colour of the surrounding text.

Clear space and minimum size

  • Clear space on every side of the mark or lockup is the width of the piece, which is 0.3 of the mark's ink height. Nothing else sits inside it.
  • The mark is never set smaller than 16 px. Below 24 px, use the tile, whose 16 and 32 px rasters are drawn on whole pixels.
  • The lockup is never set lower than 24 px.

The lockup and the property lockup

The lockup is the mark's ink at 80 units, sitting on the wordmark's baseline, with a gap of 0.3 of the mark's height. The wordmark is "idfkit", lowercase, in Inter ExtraBold at -0.035 em, outlined. The name is written idfkit, in lowercase, everywhere it appears, including at the start of a sentence.

A product or property name appears only inside the lockup: the mark, the name, a divider, and the property name set in the label face. The property is told apart in words, never by a hue of its own.

Incorrect uses

Colour

Two themes, light and dark, following the visitor's system preference. One accent, the same hue in both themes and one step apart, for the current link, the primary action and focus. Every pair below is measured by the standard's validator at every release; the ratios are WCAG 2.1 contrast, and each meets its threshold in both themes.

The sweep is a surface for nothing that must be read: hairlines, a glow, the hero's bloom.

Typefaces

Inter for text, at the weights 400, 500, 600, 700, 800; "JetBrains Mono" for code and labels, at 400, 500. Both are served from each host's own origin, as Latin subsets under the SIL Open Font License, with the fallback stacks below. No host loads a font from a third party.

Exceptions

Where a host's rendering mechanism cannot express part of the standard, the part and the reason are recorded here rather than left unstated. The list is complete: an unrecorded deviation fails that host's check.

  • mcp.idfkit.com, theme.light, since identity-2026.1: The deployment's stock API documentation pages at server.idfkit.com/docs and /redoc are served by the gateway framework and carry its own look; no visitor is sent to them, and they are outside this host. Recorded here, under the MCP property, as the one surface of the MCP product the standard does not reach.
  • app.idfkit.com, color.role.accent, since identity-2026.1: In the dark theme the role's value (blue-500, #3b82f6) measures 3.98:1 on the application's own raised surface (its neutral-800, #1e293b), under the 4.5:1 floor the application's token tests hold for links on that surface. The application aliases --accent in the dark theme to --p-brand-blue-400 (#60a5fa, 5.75:1), the next step of the same ramp; the light theme takes the role as declared.
  • auth.idfkit.com, marks/mark.svg, since identity-2026.1: the hosted widget's logo slot takes an image by URL and is left unset; the page's header carries the lockup. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, font.family.code, since identity-2026.1: the hosted widget takes one fontFamily for all its text; code and labels cannot be set in the label face. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, font.weight.semibold, since identity-2026.1: the hosted widget takes a family, not weights; its buttons and headings render at the provider's own weights. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, color.role.focus, since identity-2026.1: the hosted widget draws its own focus ring; the schema exposes no focus colour. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, color.role.link, since identity-2026.1: links inside the hosted widget take the provider's default; the schema exposes no link colour. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, family_links, since identity-2026.1: the hosted widget renders no navigation; the page around it carries the family links. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, ownership, since identity-2026.1: the hosted widget renders its own footer; the page around it carries the ownership line. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, motion.duration.base, since identity-2026.1: the hosted widget's transitions are the provider's; the schema exposes no motion. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, elevation.raised, since identity-2026.1: the hosted widget's container has no shadow property. Schema: @stytch/core 2.66.1, StyleConfig.
  • auth.idfkit.com, space.2, since identity-2026.1: the hosted widget's internal spacing is the provider's; the schema exposes only the container width. Schema: @stytch/core 2.66.1, StyleConfig.
