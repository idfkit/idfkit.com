TypeScript SDK

@idfkit/core

A sibling to the Python library rather than a transliteration of it. A synchronous core with async edges, so the same code runs in Node, a browser, a worker, or at the edge.

  • 858 generated interfaces per version
  • Real accessors, not a Proxy
  • Renames rewrite every reference
  • epJSON field names, verbatim
  • 760 example files round-trip byte-clean
  • ~36k objects/sec parse, write, re-parse

The Simulation Engine

@idfkit/engine

Loader, worker and output parsers for EnergyPlus version 26.1.0 software compiled to WebAssembly. Verified to reproduce a native build, not to approximate one.

  • Agrees with native to 3.5e−9
  • Runs off the main thread, in a worker
  • ESO, MTR, RDD, ERR and SQL parsers
  • HVACTemplate expansion built in
  • Single-threaded — no COOP/COEP
  • Engine version = package version

In the Browser

Or run the simulation
on the page.

@idfkit/engine packages EnergyPlus version 26.1.0 software compiled to WebAssembly. A model built with @idfkit/core can be solved in the browser, without a server.

Loads the live demo from shoebox.idfkit.com. About 10 MB of engine on first visit, cached afterwards — then every solve is local.

A one-zone model authored with @idfkit/core and solved by @idfkit/engine. Drag a slider and it re-solves a design day in about 50 ms — fast enough that there is no Run button. Pick a weather site and it fetches the EPW and DDY in the browser and runs all 8,760 hours in about 0.7 s.

Why idfkit

Built for performance.
Designed for humans.

Legacy tools hold you back. idfkit is built from the ground up for speed, correctness, and developer experience.

4,000x faster

O(1) dictionary-based lookups vs linear scans. On a 1,700-object IDF, idfkit is 4,000x faster than eppy.

Reference tracking

Automatic live graph of cross-object relationships. Rename a zone and every reference updates instantly.

Zero dependencies

Core library uses only the Python standard library. Optional extras for pandas, plotting, and cloud storage.

3D geometry

Built-in Vector3D and Polygon3D classes. Calculate surface areas, zone volumes, and coordinate transforms natively.

~17,300 weather stations

Search by location or coordinates. Download EPW and DDY files. Inject design days automatically.

AI-native

MCP server with 37 tools lets AI agents author, validate, and run energy simulations autonomously.

Simulation in the browser

An EnergyPlus build compiled to WebAssembly runs in a worker on the page, with no install or server. Its results match a native build to within 3.5e−9.

Every version, 8.9 to 26.1

Both libraries bundle the schemas for 17 EnergyPlus releases. A model is read and written against the version it declares.

Typed from the schema

858 interfaces generated per version, so a misspelled field is a compile error rather than a silent run-time surprise. All 17 versions ship in ~1 MB gzipped.

Intelligent code editing

Autocomplete, hover docs, signature help, and AST-based type inference for IDF files in VS Code.

Conformance, not fixtures

The test corpus is the EnergyPlus example set. All 760 files parse, write and re-parse to a deeply equal document — 290,313 objects, zero round-trip differences.

Interactive documentation

Searchable, hyperlinked EnergyPlus I/O reference with field constraints and cross-references — all in the browser.

Quick Start

Up and running
in seconds.

quickstart.py 
# Install
pip install idfkit

# Load a model
from idfkit import load

model = load("building.idf")

# O(1) lookup by name
zone = model["Zone"]["Office_Floor_1"]

# Automatic reference tracking
zone.name = "Main_Office"
# ^ All referencing objects update automatically

# Run simulation
results = model.simulate()
print(results.summary())
quickstart.ts 
// Install
npm install @idfkit/core @idfkit/schemas

import { loadIdf, saveIdf } from '@idfkit/core/node';
import type { TypeMap } from '@idfkit/core/types/v26-1';
import { createEnergyPlus } from '@idfkit/engine';

const doc = await loadIdf<TypeMap>('building.idf');

// Typed and autocompleted, from the schema
for (const zone of doc.all('Zone')) {
  console.log(zone.name, zone.ceiling_height);
}

// Renaming rewrites every reference to the old name
doc.require('Zone', 'SPACE1-1').name = 'Open Office';

await saveIdf(doc, 'renamed.idf');

// Optional: simulate with EnergyPlus compiled to WebAssembly
const ep = await createEnergyPlus({ assetBaseUrl: '/energyplus' });
const result = await ep.run({ idf, epw });
